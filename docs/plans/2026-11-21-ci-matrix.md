# Plan: the configuration matrix moves to GitHub Actions (2026-11-21)

**Status:** implemented (v2 after a fresh-context review, §6; notes in §7).
Owner request: move the matrix into a GitHub action and
replace the local matrix with a smaller set of builds that don't need WSL.

## 1. Why

- The local matrix runs six Linux configurations in WSL Debian, built from an
  rsync mirror of the Windows checkout (`docs/debugging.md`).
- **The cost:**
  - Three of the last four full runs were killed by Claude Code's
    memory-pressure reaper.
  - The mirror produced stale objects after syncs that set file times backwards.
  - Every script lives in a session scratchpad and is lost with it.
- UberTopo has no CI. litestl has one (`source/litestl/.github/workflows/ci.yml`):
  Linux gcc and clang, and Windows MSVC, all Debug.

## 2. What was checked first (2026-11-21)

- **UberTopo builds natively on Windows.** VS 18 Community ships `cl` 14.52,
  `clang-cl`, CMake 4.3.1 and Ninja 1.13.2, set up by litestl's
  `configureEnv.mjs` (vcvars64 from the newest VS).
- **Release builds under `clang-cl` and `cl` both pass all 30 tests** after two
  portability fixes in the tests:
  - `M_PI` becomes `std::numbers::pi`, the same double, so no expected values move.
  - `test_geom_predicates` gets its missing `#include <array>`.
- The five compile-fail and compile-ok tests are skipped under MSVC-style
  drivers by design (`tests/CMakeLists.txt`), which explains 30 against Linux's 35.
- `clang-cl` gives 0 warnings. `cl` gives only litestl's `C4068` (unknown
  `#pragma STDC`) in `expansion.h`, 10 times.
- `cl` has no `__int128`, so it exercises litestl's portable wide-integer path.
  Locally that path was previously reached only by litestl's `clang-noint128`.

## 3. Design

### 3.1 `CMakePresets.json` at the repo root (one source of truth)

- **Configure presets.** Ninja generator, `binaryDir` `${sourceDir}/build/${presetName}`
  (`build/` is already ignored).

  | Preset | Host | Compiler | Type | Flags |
  |---|---|---|---|---|
  | `clang-rel` | Linux | clang | Release | |
  | `gcc-rel` | Linux | gcc | Release | |
  | `clang-v3` | Linux | clang | Release | `-march=x86-64-v3` |
  | `gcc-asan` | Linux | gcc | Debug | `-fsanitize=address -fno-omit-frame-pointer` |
  | `gcc-ubsan` | Linux | gcc | Debug | `-fsanitize=undefined -fno-sanitize-recover=undefined` |
  | `gcc-tsan` | Linux | gcc | RelWithDebInfo | `-fsanitize=thread -DLITESTL_ATTR_CHECKS=1` |
  | `clang-cl-rel` | Windows | clang-cl | Release | |
  | `msvc-rel` | Windows | cl | Release | |

  - The flags are those of the retired `matrix.sh`. Sanitizer flags go into
    `CMAKE_C_FLAGS`, `CMAKE_CXX_FLAGS` and `CMAKE_EXE_LINKER_FLAGS`.
  - Host conditions keep each preset to its OS.
- **Test presets** carry the environment:
  - `LITESTL_TEST_NO_BREAK=1` everywhere;
  - `LITESTL_TEST_SCALE_DIV=4` for the three sanitizer presets;
  - `UBSAN_OPTIONS=print_stacktrace=1` for UBSan;
  - output on failure, and a 1800 s timeout.
- **Workflow presets** (configure, build, test) give one command per configuration:
  `cmake --workflow --preset <name>`.

### 3.2 `.github/workflows/ci.yml`

- **Triggers:**
  - push to any branch (v2, R1);
  - pull requests to `master`;
  - `workflow_dispatch`.
- A newer push to the same ref cancels the run in progress.
- **`linux` job:**
  - Runs on `ubuntu-24.04`, matrixed over the six Linux presets, with `fail-fast: false`.
  - Checkout with `submodules: true`. litestl has no nested submodules, and Eigen
    is vendored.
  - Installs `ninja-build` (the image ships gcc 13, clang 18 and CMake).
  - TSan only: `sudo sysctl vm.mmap_rnd_bits=28`. This is the root fix for the
    "unexpected memory mapping" failure that WSL worked around with `setarch -R`.
  - Runs `cmake --workflow --preset ${{ matrix.preset }}`.
  - Uploads `build/<preset>/Testing/Temporary/LastTest.log` on failure.
- **`windows` job:**
  - Runs on `windows-latest`, matrixed over `msvc-rel` and `clang-cl-rel`.
  - `actions/setup-node`, then
    `node source/litestl/configureEnv.mjs cmake --workflow --preset <name>`.
  - No third-party actions.
- **Compiler versions:** CI gets gcc 13 and clang 18, while the old WSL matrix
  had gcc 14 and clang 19. If either fails on a real language gap, install
  `g++-14` (in noble) and pass `CC`/`CXX` through the preset's `$env{}`. Don't
  lower the code to the old compiler without asking.

- **v2:** the review changed parts of this section, as follows.
  - A `clang-noint128` preset and `UT_LITESTL_TESTS=ON` on Linux restore
    litestl's coverage (R2).
  - `msvc-asan` joins the Windows job (R3).
  - Test presets run 8 jobs (R4).
  - Sanitizers go through the `UT_SANITIZE` cache variable, not hand-set flag
    strings. Setting `CMAKE_CXX_FLAGS` would replace MSVC's defaults (`/EHsc`).

### 3.3 The local check: `tools/check.mjs`

- `node tools/check.mjs [preset...]` runs the workflow presets under
  `configureEnv.mjs`. The default is `clang-cl-rel` and `msvc-asan` (v2, R3).
  - It writes each preset's output to `build/<preset>.log`.
  - It prints one line per preset (build ok/failed, the warning count, ctest's
    summary) and exits non-zero if any preset failed.
- Its warning count is the gate that `b.sh` used to provide. It counts distinct
  warnings in `source/ubertopo` only. `--clean` gives a full count, for phase
  gates (v2, R5).
- It runs the presets one after another. Each uses Ninja's default parallelism,
  which on this 16-thread, 31 GB host is far below the memory that WSL's VM
  reserved.
- Mutation runs stay a session tool. They build natively in a build directory
  of their own, such as `build/mut-clang-cl-rel`, so a mutant never lands in a
  tree that `check.mjs` reuses (R9). There's no mirror and no sync.

### 3.4 What "the matrix passes" now means

- A phase is done when:
  - `tools/check.mjs` passes locally (both Windows presets, 0 new warnings);
  - CI is green on the pushed branch or PR (all ten configurations).
- **Pushing needs the owner.** I don't push UberTopo branches unasked, so CI runs
  when the owner pushes or asks me to. Until then, phase notes say "local check
  passed; CI pending".

### 3.5 Docs

- **New `docs/building.md`:** the presets, the local check, CI, and what each
  configuration is for. Listed in `docs/index.md`.
- **`docs/debugging.md`:** the WSL entries stay as history, with a line saying the
  WSL matrix was retired and pointing to `building.md`.

## 5. Risks

- **The first CI run is the real test.** Each preset is run locally only on its
  own OS family:
  - the Windows presets here;
  - the Linux presets only through the old scripts' identical flags.
- **Time:** six Linux builds and two Windows builds on 4-core runners. The ASan
  Debug build is the slowest. Tests labelled `long` stay in.
- **`windows-latest` (VS 2022):** `configureEnv.mjs` maps directory `2022` to
  version 17. The clang-cl component is in GitHub's VS 2022 image.

## 6. Review (fresh context, 2026-11-21, of v1)

Findings, most severe first, and what changed:

- **R1, confirmed: CI would never run on a session branch.** v1 triggered only
  on `master`, PRs and `workflow_dispatch`, and `workflow_dispatch` needs the
  file on the default branch. *Changed:* push to any branch triggers CI.
- **R2, confirmed: litestl's matrix was dropped.**
  - The old `all.sh lst` ran 7 litestl configurations, `clang-noint128` among
    them. UberTopo forces `LITESTL_BUILD_TESTS` off.
  - litestl's own CI is Debug only, with no sanitizers.
  - *Changed:* a `UT_LITESTL_TESTS` option, on in the Linux presets, and a
    `clang-noint128` preset.
- **R3, confirmed: the local gate had no sanitizer and no gcc.** *Changed:*
  `msvc-asan` replaces `msvc-rel` in the local default. It still uses `cl`, so
  the portable wide-integer path keeps its local coverage. gcc and the
  compile-fail tests are CI-only.
- **R4, confirmed: ctest ran serially.** `matrix.sh` used `-j $(nproc)`.
  *Changed:* the test presets set 8 jobs.
- **R5, plausible: the warning count.** Ninja reports warnings only for the files
  it recompiles, and `cl` has a litestl baseline (`C4068`). *Changed:* only
  UberTopo's own warnings count, and `--clean` gives a full count.
- **R6, plausible: the submodule commit must be on GitHub.** *Changed:* noted
  in the workflow and in `building.md`.
- **R7, low: the vcvars path is new on GitHub.** litestl's Windows CI uses the VS
  generator instead. `configureEnv.mjs` handles both VS 2022 and VS 2026
  folders, so it is left as is. The first run will tell.
- **R8, low: N-API is on locally only if the headers are fetched.** They aren't
  fetched today. No change.
- **R9, minor:** `apt-get update` added before installing Ninja. `g++-14` is on
  the image if needed.
- **Confirmed fine:**
  - the flags match `matrix.sh`;
  - preset schema v6 works with the CMake 3.20 minimum;
  - sanitizer flags reaching litestl is intended;
  - there is no checkout-path constraint;
  - the C++20 features in use are supported by gcc 13 and clang 18;
  - the TSan sysctl is correct.

## 7. Implementation notes

- **`msvc-asan` exposed a slow test oracle.** `test_geom_cdt` took 808 s under
  MSVC ASan, against 113 s under gcc-asan and 9 s in Release.
  - UberTopo's copy of the BigInt oracle (`tests/support/bigint_oracle.h`) was
    the old version, before litestl `9a2cd92`, and copied `std::vector` limbs on
    every determinant expansion. MSVC's ASan allocator is slow.
  - *Fix:* synced the oracle from litestl at `2360bc9`.
- **clang-cl warned about `getenv` in a clean build** (5 warnings in the tests,
  `-Wdeprecated-declarations`). The trial build in §2 counted only the files it
  recompiled, as R5 predicted. *Fix:* `_CRT_SECURE_NO_WARNINGS` under
  MSVC-style drivers, in the root `CMakeLists.txt`.
- **Local check times** (clean, 16 threads):
  - `clang-cl-rel` takes 86 s;
  - `msvc-asan`'s tests take 87 s, down from 13.5 min, after the oracle sync.
- **First CI runs (2026-11-21).** All three Windows jobs passed on the first
  run, so the `configureEnv.mjs` path works on `windows-latest` (R7). TSan
  passed with the sysctl. litestl's tests, now under sanitizers for the first
  time, failed twice:
  - **gcc-ubsan:** litestl's binding code cast `Array<T>` and `Struct<T>`
    bindings to other specialisations (`Array<void>`, `Array<BindingBase>`,
    `Struct<void>`), which UBSan reports as a bad downcast.
  - **gcc-asan:** `test_binding_iface`'s intentional descriptor leak wasn't
    matched by `lsan.supp`.
  - Both are fixed in litestl PR #7, merged as `9f1744e`. UberTopo's gitlink
    points there, and CI passes all ten configurations on it.
  - The third run passed all ten configurations, each in 2–8 min.
