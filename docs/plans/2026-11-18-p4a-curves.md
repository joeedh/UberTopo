## 1. Split: P4a now, P4b next

P4 as listed is two phases of work. Like P3, it is split.

**P4a (this plan): exact curves as edge carriers.**
- A `curves/` library of exact, certified 2D and 3D curves.
- Certified polynomial approximation (quintic Hermite B-splines) and flattening.
- The geometry store in `Complex`, following the pool owner contract.
- Edge carriers (`.e.curve` + `.e.range`) in the editor, the validator and I/O.

**P4b (later plan): surfaces and the road acceptance case.**
- Surfaces: an explicit `Plane`, `RoadSurface(s, t)`, `Heightfield`.
- Pcurves on coedges and on edges embedded in faces.
- Cross-sections, superelevation and gravity-referenced frames.
- Projection, closest point and intersection queries.
- Curved-geometry validation that replaces the chord skeleton (OI-P4a-1).
- Builder support, Bertolazzi–Frego G1 fitting, non-polynomial κ laws.
- The acceptance case: a road imprinted on terrain sheets.

P4a's acceptance: certified-bound tests and oracle comparison for every P4a kind, and
curved edges that survive the full edit, undo, freeze and I/O cycle.

## 2. Decisions (proposed DEC-018)

- **Library.** `source/ubertopo/curves/`, namespace `ubertopo::curves`. Evaluation is
  in `double`, in the tile frame's local coordinates (the same frame-local doubles as
  `geom::to_double3`). Nothing here is templated on the coordinate type (05 §2).
- **κ laws are polynomials of degree ≤ 3 in P4a.** This covers lines, arcs,
  clothoids, cubic spirals and Bloss transitions. θ(s) is then a polynomial, which
  makes every bound below exact polynomial algebra. Sine, cosine, log-aesthetic and
  higher-degree IFC spirals are P4b (OI-P4a-3).
- **Certification method.** Every kind reports:
  - an **evaluation error bound** (`eval_error`): the distance between the computed
    and the exact point of its definition;
  - **derivative bounds** (`deriv_bound(t0, t1, k)`): an upper bound on
    max |r⁽ᵏ⁾| over a range.

  Bounds, flattening and Hermite approximation are generic algorithms over these two.
  "Certified" means: proved for exact arithmetic, plus an explicit floating-point
  rounding allowance, and checked against a quad-precision oracle.
- **G2 by default.** The approximation is a quintic Hermite B-spline parameterised by
  the source parameter, with knots at every special parameter: C2, so curvature is
  exact at the joins. Septic (G3) is P4b, if rail needs it.
- **`GeomRef` becomes `attr::PoolRef`** (8 bytes). The geometry store is a
  `PoolStore` held by value in `Complex`, with kinds registered in a fixed order.
- **Collect points are explicit.** The store is collected only by barriers
  (`compact`, `rebuild_regions`) and by `Editor::collect_geometry()`, never on a
  threshold inside commits. So a ref the caller holds stays valid until the caller
  reaches one of those points (OI-P4a-2).
- **Endpoint tolerance.** An edge's carrier must meet its end vertices within
  `eval_error + rounding_C(p) + curve_tol`.
  - `rounding_C(p)` is the coordinate type's rounding at that position: half the
    quantum per axis for `Lattice`, ½ ulp per axis for `double` and `float`.
  - `curve_tol` is a new global attribute (`.g.curve_tol`), default 2⁻³⁰ frame units.
- **Chord skeleton.** The geometric validator keeps checking straight chords between
  vertices. A curved edge's carrier is checked for kind, range and endpoints only.
  Curved-geometry validity is P4b (OI-P4a-1).
- **UTCX format 3** stores the geometry store. The goldens are re-pinned once, for the
  reasons in §5.4.

## 3. The curves library

### 3.1 Polynomials and piecewise functions (`curves/poly.h`, `curves/fn1d.h`)

- `Poly`: up to degree 63, coefficients in `double`.
  - Operations: evaluate (Horner), differentiate, integrate, multiply, shift and scale
    the variable.
  - **Range bound** over an interval: map to [0, 1], convert to Bernstein form, and
    take the coefficients' extremes. The convex hull property makes this a certified
    bound, inflated by the conversion's rounding.
  - **Real roots in an interval:** isolate by Bernstein sign changes and bisection,
    then refine with Newton. A fixed iteration count keeps it deterministic.
- `Fn1D`: a piecewise polynomial in station, with explicit breakpoints.
  - Used for lane widths w(s) and vertical profiles z(s).
  - Canonical form: trailing zero coefficients trimmed, −0.0 → +0.0, and equal
    adjacent pieces merged. Equal functions therefore intern to one entry.

### 3.2 The kind interface (`curves/curve.h`)

```cpp
enum class ParamKind : uint8_t { ArcLength, Station, General };

template <int D> class CurveEval {            // D = 2 or 3
public:
  virtual Interval domain() const = 0;
  virtual ParamKind param_kind() const = 0;
  /* r, r', ..., r^(n) at t, n <= 6 */
  virtual void eval(double t, int n, Vec<D> *out) const = 0;
  /* certified: |computed r(t) - exact r(t)| <= eval_error() for t in the domain */
  virtual double eval_error() const = 0;
  /* certified: max over [t0, t1] of |r^(k)|, k = 1..6; +inf where r is not C^k */
  virtual double deriv_bound(double t0, double t1, int k) const = 0;
  /* parameters where smoothness drops (segment joins, breakpoints, folds), sorted */
  virtual void special_params(double t0, double t1, Vector<SpecialParam> &out) const = 0;
};
```

- **Dispatch is virtual, per kind** (05 §2): there is no switch over kinds.
- A kind registers a `KindOps` object that builds a `CurveEval` from a store entry.
  The pool ID selects the `KindOps` from a table filled at registration.
- **A `CurveView`** (store, ref) → evaluator stays valid until the next `intern` or
  `collect` on that store.
- **Inner refs are resolved when the view is built.** For example, `alignment3`
  resolves its horizontal curve then.

### 3.3 `cesaro2`: planar curvature-law curves

**Definition:**
- a start pose (x₀, y₀, θ₀);
- segments `{L_i, κ_i(σ)}`, where κ_i is a polynomial of degree ≤ 3 in the local arc
  length σ ∈ [0, L_i].

Segments chain: each starts at the previous segment's end pose. Heading is continuous,
and κ may jump at a join. The parameter is the arc length s ∈ [0, ΣL_i].

**Canonical form:**
- κ coefficients go through `Fn1D`'s rules;
- zero-length segments are dropped;
- −0.0 → +0.0;
- θ₀ is reduced to (−π, π].

Equal definitions therefore produce bitwise-equal entries and intern to one entry.
Hashing, equality and I/O cover the definition only.

**Derived pieces.** The derived piece table is rebuilt by `read`, so it is never
written. Pieces are built at construction:
1. Start from the segments. Each segment's θ is a polynomial: θ₀ plus the exact
   integral of κ.
2. Expand each piece around its midpoint m: Q(u) = θ(m + u) − θ(m), for |u| ≤ r = h/2.
   - The integrand e^{iQ(u)} has a Taylor series Σ e_k u^k, computed to order
     N = 30 by the recurrence e_{k+1} = (i/(k+1)) Σ_j (j+1) q_{j+1} e_{k−j}.
   - Integrating term by term gives the piece's position polynomial.
3. **Tail bound (certified).** Let Q̂(u) = Σ_j |q_j| u^j.
   - The series of e^{Q̂} majorises e^{iQ} coefficient by coefficient.
   - Compute its coefficients ê_k up to K = 160. The tail beyond N is then at most
     Σ_{N<k≤K} ê_k r^k + e^{Q̂(R)} (r/R)^{K+1} / (1 − r/R), with R = 4r.
   - Both terms are sums of positive numbers, so there is no cancellation.
   - The tail of the integral is at most 2r times that.
4. **Bisect** each piece until its certified tail is at most 2⁻⁵⁴·h and its bend
   Q̂(r) is at most 0.5. Bisection is a deterministic function of the definition.
5. Each piece stores:
   - its start point, chained with compensated summation;
   - θ(m);
   - the 31 complex coefficients;
   - its error budget: tail + Horner rounding (γ₆₂ Σ ê_k r^{k+1}) + rotation rounding.

**Evaluation and bounds:**
- **`eval(s)`:** find the piece by binary search, evaluate the polynomial by Horner,
  then rotate by e^{iθ(m)}.
- **Derivatives** come from θ directly, not from the cache: r' = e^{iθ}, and
  r⁽ᵏ⁺¹⁾ = P_k(s) e^{iθ}, with P_1 = 1 and P_{k+1} = P_k' + iκ P_k.
- **`eval_error`:** the sum of the piece budgets over the curve (start-point errors
  accumulate) plus the heading rounding × length.
- **`deriv_bound(k)`:** for k ≥ 2, |P_k| is bounded by the Bernstein bounds of
  Re P_k and Im P_k on each segment overlapping the range. The degree is at most
  (k−1)·3 ≤ 15 for k ≤ 6. Across a join only the derivatives up to κ's continuity are
  finite; higher ones are reported as +inf, which forces a split at the join.
- **Special parameters:**
  - segment joins;
  - inflections (roots of κ);
  - curvature extrema (roots of κ').

### 3.4 `offset2`: variable offsets of the exact base

- **Definition:** base = a `PoolRef` to a `cesaro2`, plus w = an `Fn1D` over the
  base's station. It has inner refs.
- **Evaluation** uses the exact base:
  - r_w(s) = r(s) + w(s)·N(s), with N = i·e^{iθ};
  - r_w' = (1 − wκ + i w') e^{iθ}, and higher derivatives follow the same P-style
    recurrence, starting from Q_1 = 1 − wκ + i w'.

  It never offsets an approximation (05 §4).
- **The parameter is the base station** (`ParamKind::Station`).
- **Folds:** the roots of 1 − wκ on each piece are special parameters, found by exact
  polynomial roots. `offset_valid(t0, t1)` reports whether 1 − wκ > 0 on the whole
  range.
- **Canonical form:** an offset of an offset is not created. The constructor resolves
  it to a single offset of the root base with w₁ + w₂, and a zero width collapses to
  the base itself.
- **Bounds:** `eval_error` = base error + rounding of the w·N term.

### 3.5 `alignment3`: horizontal × vertical profile

- **Definition:**
  - horizontal = a `PoolRef` to a `cesaro2` or `offset2`;
  - profile z = an `Fn1D` over the horizontal's parameter.

  The parameter is the horizontal station (`Station`).
- **Evaluation:** r(s) = (h(s), z(s)). Its derivatives are those of the horizontal
  and the profile.
- **Bounds:** deriv_bound = √(bound_h² + bound_z²), and the special parameters are
  the union of both components'.
- **Role.** This is the 3D carrier kind for road and rail centrelines and lane edges.
  Cant and superelevation belong to P4b's `RoadSurface`, not to the curve.

### 3.6 `catenary3`, `polyline3`, `bspline`

**`catenary3`:**
- **Definition:** anchors A and B, plus the catenary constant a > 0. The curve lies in
  the vertical plane through A and B: r(x) = A + x·û + (f(x) − f(0))·ẑ, with
  f(x) = a·cosh((x − c)/a) and x ∈ [0, d].
- c is derived in closed form (via asinh) so that the curve passes through B.
- `from_sag(A, B, sag)` solves for a with a fixed number of Newton steps.
- **Bounds:** the derivatives are a^{1−k}·cosh or sinh, so they are bounded by their
  values at the range ends (cosh and |sinh| are monotone away from c). `eval_error`
  allows a few ulp of libm's cosh (OI-P4a-4).

**`polyline3`:**
- **Definition:** points; the parameter is the index, t ∈ [0, n − 1]. It is exact.
- Every vertex is a special parameter, and deriv_bound(k ≥ 2) = 0 inside a span.

**`bspline`:**
- **Definition:**
  - dimension 2 or 3;
  - degree ≤ 7, with clamped knots and control points; non-rational in P4a;
  - optionally a source `PoolRef`, a source range and `max_error`, which make it an
    approximation cache. It has inner refs.
- **Evaluation:** de Boor; derivatives through derivative control points.
- **Bounds:** deriv_bound converts the spans in range to Bézier form (by knot
  insertion), then takes the Bernstein bound of the k-th derivative.
- **Special parameters:** knots whose multiplicity lowers continuity.

### 3.7 Generic algorithms (`curves/approx.h`)

**Box bound.** `bounds(view, t0, t1)` returns the endpoints' box, widened by:
- h²/8 · √D · deriv_bound(t0, t1, 2), the error of linear interpolation;
- `eval_error`.

It subdivides at special parameters and wherever deriv_bound(2) is infinite.

**Flattening.** `flatten(view, t0, t1, tol)` returns sorted parameters whose polyline
lies within tol of the curve.
- Start from the special parameters, then bisect recursively until
  h²/8 · √D · M₂ ≤ tol − eval_error.
- Bisection from the same root partition makes the parameter sets of tol and tol/4
  nested, so LODs nest.

**Approximation.** `approximate(store, ref, t0, t1, tol)` interns a quintic `bspline`
cache whose distance from the exact curve is at most `max_error` ≤ tol. It is
parameterised by the source parameter (so no parameter map is needed), and the source
is an inner ref.
- **Pieces:** start from the special parameters. On each piece, take Hermite data
  (r, r', r'') at both ends from `eval`.
- **Error bound per piece:**
  - h⁶/(2⁶·6!) · √D · deriv_bound(piece, 6), the interpolation bound;
  - plus the data error propagated through the Hermite basis: its Lebesgue constants,
    times `eval_error` and the derivative evaluation errors;
  - plus the rounding of the Bézier conversion.
- **Bisect** while the bound exceeds tol. Bisection is deterministic.
- **Assembly:** the pieces join C2 in the source parameter, so they assemble into a
  degree-5 B-spline with knots of multiplicity 3.

**Arc length.** Exact for `ArcLength` kinds. A general certified arc length is P4b.

### 3.8 The oracle (`tools/curve_oracle/`)

- **A GCC-only tool,** using `__float128` and libquadmath. It is never linked into
  the core and never in ctest (DEC-002 permits offline oracles).
- **Method:** independent of production. It runs composite Gauss–Legendre directly on
  e^{iθ(s)}, with nodes computed in quad precision.
  - It uses two panel counts, which must agree to 10⁻²⁸.
  - It evaluates θ, w, κ and the catenary's cosh in quad.
- **Output:** `tests/data/curve_oracle.inc`, which holds reference points and tangents
  for a fixed set of curves (§6), as hex doubles. The file is checked in, so the tests
  run the same in every configuration. The tool is rebuilt and rerun by hand when the
  fixture set changes.

## 4. The geometry store in `Complex`

### 4.1 Store and columns

- **The store.** `Complex` gains `attr::PoolStore geom`. Kinds are registered in the
  constructor in this order: `cesaro2` = 1, `offset2` = 2, `alignment3` = 3,
  `catenary3` = 4, `polyline3` = 5, `bspline` = 6. New kinds are appended.
- **`topo::GeomRef`** becomes an alias of `attr::PoolRef`.
  - `Geom<Name>` columns become `attr::Column<attr::PoolRef>`.
  - The old 4-byte placeholder (`types.h`) and its `ValueKey` are removed.
- **New columns:**
  - `.e.range`: `Column<math::double2>`, Topo, default (0, 0);
  - `.g.curve_tol`: `Column<double>`, a global row, default 2⁻³⁰.
- **Copy and move stay defaulted** (07 §13).

### 4.2 Roots and accepted kinds

- **Roots:** all domain groups in schema order, plus `global`.
- **The editor adds `JournalRoots`.** Op payloads that hold refs are visited too
  (§5.2).
- **`Roots::accept`:**
  - `.e.curve` accepts the 3D kinds only: `alignment3`, `catenary3`, `polyline3`, and
    `bspline` with D = 3.
  - `.c.pcurve` and `.f.surface` accept nothing in P4a.
  - Inner refs follow each kind's rules: `offset2.base` must be `cesaro2`, and
    `alignment3.horizontal` must be `cesaro2` or `offset2`.

### 4.3 Hashes, freeze and I/O

- **`content_hash` and `topology_hash`:**
  - If the store has no live entry, they hash the groups as now (fast path).
  - Otherwise they hash a canonicalised copy of the complex (O(pages)), so the hash is
    independent of the insertion order. `content_hash` also includes the canonical
    store hash; `topology_hash` does not.
- **`freeze`** canonicalises the store after its permutes, with the domain groups as
  roots (07 §13).
- **`compact`** leaves the store alone: refs live in rows, and permutes keep them
  valid.
- **`write` (format 3):** header, floors, then the canonical store, then the groups.
  It writes from a canonicalised copy.
- **`read` follows the strict owner sequence:**
  1. a fresh complex;
  2. `store.read`;
  3. the group reads;
  4. `audit(require_reachable)`;
  5. `canonicalize`, which must report no change;
  6. move-assign.
- **Formats 1 and 2** still read. Their placeholder `Geom` columns must be all NONE;
  they map to `kNoRef`, and any other value is refused.

## 5. Editing

### 5.1 Edge carrier semantics

- **Meaning.** `.e.curve` = ref and `.e.range` = (t₀, t₁) mean that vertex `vs[0]` is
  at carrier(t₀) and `vs[1]` at carrier(t₁).
  - t₀ > t₁ is allowed: the edge runs against the carrier's direction. This lets two
    opposite edges share one carrier.
  - The two ends must differ: t₀ ≠ t₁.
- **NONE** means a straight segment, and its range must be (0, 0).
- **Sharing.** Many edges may share one carrier with different ranges. This is how
  split halves and adjacent lanes stay consistent: by sharing, not by tolerance.

### 5.2 Primitives

- **`intern_curve(def) → PoolRef`** canonicalises and interns. It is not journaled:
  an unreferenced entry is not content.
- **`set_edge_curve(e, ref, range)`:**
  - **Checks:** e is live; ref is NONE or live and of an accepted kind; the range lies
    in the domain.
  - **Effects:** writes both columns through `touch`. The endpoint check is left to
    validation (§5.3).
  - **Journal:** `OpKind::SetEdgeCurve`, u = [e, pool, slot, t₀ bits, t₁ bits].
  - `JournalRoots` visits the ref, so undo, redo and later collects keep the entry.
- **`split_edge_at(e, t, &v, &e2)`** splits a curved edge at carrier parameter t,
  strictly inside the range.
  - The new vertex is placed at `round_C(carrier(t))`.
  - The children take the ranges (t₀, t) and (t, t₁), sharing the ref.
  - IDs, slots and propagation are as in `split_edge`.
- **`split_edge(e, p)`** on a curved edge is refused with `CurvedEdge`, because the
  parameter is unknown.
- **`join_edge(v)`** on curved edges requires:
  - the same ref;
  - ranges that meet at v's parameter and continue in the same direction.

  The joined range is their union. Otherwise it fails with `Incompatible`. The
  collinearity test applies to straight edges only.
- **`weld`** fuses parallel edges only if both are straight, or both have the same ref
  and range. Otherwise it fails with `Incompatible`: P4a has no curved digons
  (OI-P4a-1).
- **No other primitive changes.**
  - `imprint`, `unimprint`, `split_face`, `add_hole` and `remove_hole` move edges
    between loops but keep `.e.curve` and `.e.range` as they are.
  - `kill_edge` frees the row.
  - Physical undo restores both columns from row captures, as it does for every other
    column.
- **`collect_geometry()`** collects with the complex groups and `JournalRoots` as
  roots. Barriers call it after they run.

### 5.3 Validation

- **New codes** in the embedding layer:
  - `CurveKind`: the ref is not live, or its kind is not accepted;
  - `CurveRange`: the range lies outside the domain, the ends are equal, or a NONE ref
    has a non-zero range;
  - `CurveEndpoint`: an end vertex lies further than the §2 tolerance from the carrier.
- **`GeometryUnsupported`:** a non-NONE `.c.pcurve` or `.f.surface`.
- **Local validation** checks the listed edges. The editor's touched-row filter
  already lists every edge whose vertices or columns changed.
- **The skeleton check is unchanged:** faces and wires are validated on their chords
  (OI-P4a-1).

### 5.4 Goldens

- **Why every hash changes:**
  - the `Geom` columns widen from 4 to 8 bytes;
  - `.e.range` and `.g.curve_tol` are added;
  - the random step mix gains curve steps.
- **Proof that only those causes moved the hashes** (W5):
  - before the switch, record each golden scenario's content hash with the `Geom`
    columns excluded;
  - after the switch, recompute it with `Geom`, `.e.range` and `.g.curve_tol`
    excluded;
  - the two must be equal.

  The comparison lives in a temporary `CLAUDENOTE:` test hook and is removed after use.
- **Re-pinned once** in W5 (the P2 determinism golden and the random test's seeds 1–3
  without curve steps), and again in W6 after the curve steps are added. The plan
  records both sets.

## 6. Tests

**Library tests:**
- **`test_curves_poly`:**
  - Horner, derivative and integral identities;
  - Bernstein range bounds contain 10⁴ samples, and are tight for monotone cubics;
  - roots are found to 1e-14 on curves with known roots, including double roots and
    roots at the interval ends.
- **`test_curves_cesaro`:**
  - **Oracle:** for line, arc, clothoid (κ: 0 → 1/600 over 150 m), a tight clothoid
    (0 → 1/15), a Bloss transition, an S-curve with an inflection, a 10 km chain of
    200 segments, and a very long, slow spiral (κ' = 1e-9):
    - |eval − oracle| ≤ eval_error;
    - eval_error ≤ 1e-9 m on the 10 km chain.
  - **Exactness and invariance:**
    - arc length equals the parameter;
    - splitting a segment at σ and re-evaluating agrees within the sum of the error
      bounds;
    - reversal negates curvature;
    - a rigid motion commutes with evaluation.
  - **Canonical form:** −0.0, trailing zeros and zero-length segments intern to one
    entry.
- **`test_curves_approx`:**
  - `bounds` contains 10⁴ samples per kind;
  - flattening deviation ≤ tol at sampled parameters, and the tol/4 set contains the
    tol set;
  - the measured `approximate` error (10⁴ samples per piece against the exact curve)
    is ≤ max_error for every P4a kind;
  - the bound is no more than 1000× the measured error (reported);
  - joins are C2: r'' agrees to rounding at every knot.
- **`test_curves_kinds`:**
  - **`offset2`:** matches the oracle; a fold is found where w·κ = 1 on a clothoid
    whose curvature crosses 1/w at a known s; an offset of an offset collapses to one
    entry.
  - **`alignment3` and `catenary3`:** match the oracle; `from_sag` gives the requested
    sag.
  - **`polyline3`:** evaluation and its special parameters.
  - **`bspline`:** de Boor against Bernstein evaluation; knot insertion keeps the
    shape.

**Store, complex and editor tests:**
- **`test_geom_store`:**
  - interning deduplicates;
  - inner refs keep their targets (an `alignment3` keeps its `cesaro2` alive through a
    collect);
  - `Roots::accept` refuses a 2D kind on `.e.curve`;
  - two insertion orders give equal `content_hash` and equal written bytes;
  - write/read round trip;
  - a corrupted stream (a dangling ref, a non-canonical store) is refused;
  - formats 1 and 2 still read.
- **`test_edit_curves`:**
  - `set_edge_curve` with a valid arc carrier, and with a carrier that misses its end
    vertex (`CurveEndpoint`);
  - undo and redo are bit-identical;
  - `split_edge_at` then `join_edge` restores the content hash;
  - `join_edge` with non-abutting ranges, or with different refs, fails `Incompatible`;
  - `split_edge` on a curved edge fails `CurvedEdge`;
  - **the journal keeps entries alive:** set a carrier, replace it, `collect_geometry`,
    undo (the old carrier comes back), and redo. Run this with
    `set_reuse_freed(false)`, so a dangling ref is reported;
  - freeze, write and read with curved edges.
- **`test_edit_random`** gains curve steps:
  - set an arc or clothoid carrier between an edge's endpoints (built through them);
  - clear a carrier;
  - `split_edge_at` and join;
  - `collect_geometry` every 50 steps.

  Local still equals Full by hash, and OnCommit runs are unchanged. The goldens are
  re-pinned (§5.4).

**Benchmark.** `bench_curves` (not in ctest) reports, without gating:
- `cesaro2` evaluation throughput;
- the approximation's piece counts and times for a highway clothoid at 0.1 mm and a
  15 m junction corner (compare with the research estimate of "a handful");
- offset approximation;
- the bound-to-measured ratios.

1. `eval_error` returns 0 for `cesaro2`.
2. Taylor order N = 30 → 8.
3. Piece bisection skipped (one piece per segment).
4. The majorant uses q_j instead of |q_j|.

## 9. Open issues

- **OI-P4a-1 — curved geometry is validated on its chord skeleton.** A carrier can
  cross geometry its chord avoids. Certified tube tests replace this in P4b. Until
  then, generators must keep carriers within the clearance their chords imply.
- **OI-P4a-2 — no automatic collect.** Unreferenced entries accumulate until a barrier
  or `collect_geometry()`. P4b's generators collect at batch ends.
- **OI-P4a-3 — κ laws of degree ≤ 3 only.** Non-polynomial laws need a different
  derivative bound.
- **OI-P4a-4 — determinism of libm.** sin, cos (piece rotations) and cosh (catenary)
  come from the platform libm. Results are bit-identical per platform (design 04 §8),
  and both of our compilers use glibc.
