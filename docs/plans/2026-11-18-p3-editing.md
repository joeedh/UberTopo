## 1. Baseline (verified 2026-11-18 against master `da0ca82`)

**Nothing in P2 is incremental:**
- the builder links every disk and radial cycle in one bulk pass;
- `validate` and `build_regions` work on the whole complex only;
- no helper inserts or removes a single edge in a disk cycle, or a single coedge in a
  radial cycle.

**Link invariants that edits must keep** (schema.h, builder.cc, validate*.cc):
- **Disk cycles.** `.e.disk` is `[2·slot] = prev`, `[2·slot+1] = next`, with packed
  `(edge << 1) | slot`. `.v.e` is any incident edge; the builder uses the smallest.
- **Radial cycles.** `.c.radial_next/prev` run counter-clockwise about `vs[0]→vs[1]`.
  **`.e.c` must be the coedge whose face has the smallest persistent ID.** The embedding
  validator starts the comparison there.
- **Coedge sense.** The `Sense` bit means the coedge runs `vs[0]→vs[1]`, and the wedge
  rule is `side_toward_next = sense ? FRONT : BACK`.
- **Loops.** `.l.next` is singly linked and ends at `NONE`. `.f.l` is the first loop as
  emitted; the outer loop is derived geometrically. Loop IDs are
  `loop_id(face_id, ordinal)`.
- **Regions.** `.f.region`, `.f.shell`, `.fs.*`, `.s.*` and `.r.*` are written only by
  `build_regions`, which replaces the shell and region domains wholesale.
- **Region identity.** Region IDs and shell order derive from **minimum face-side IDs**
  (`region_id(hint, min side)`, shells indexed by their minimal side). So any edit that
  creates a face can change region IDs and shell indices as `build_regions` would
  compute them.

**Domains:**
- `Domain::free` resets every column except `.gen`, bumps `.gen`, and pushes onto a LIFO
  free list. It doesn't check liveness, and it unlinks nothing.
- `rebuild_allocator` (after `read` and `permute`) rebuilds the free list
  *descending*.
- `FaceDomain` keeps the side rows in step, but **hides rather than overrides** the base
  methods.

**Radial order.** `radial_order` sorts a *whole* cycle, with ties reported. Half-planes
come from the face frame (planar faces) or from the third vertex of the `T(f)` triangle
(projected faces).

**Reusable pieces:**
- freeze's `identity_map` and `new_generations` (freeze.cc, anonymous namespace), and
  `remap_group` with `RemapRule`s;
- the validator's combinatorial `Checker` and its geometric checks, all whole-complex
  today;
- `test_topo_freeze.cc:47–121`, the only existing hand-written kill code (fences and
  wires).

**Hashes.** `content_hash` and `topology_hash` cover `.gen`, `.live` and freed rows, so
tombstones and generations are part of the hash.

## 2. Scope: P3a now, P3b after

**P3a** (this plan's work items):
1. **`Editor<C>` with transactions.** Every primitive is a transaction. A failed
   transaction rolls back exactly, and a committed one can be undone and redone.
2. **Physical undo journal** with logical op records and ID lineage. It is a
   `RefRoot`.
3. **Propagator.** Topology events become `MixBatch`es per domain and per event kind,
   with policies taken from per-column rules.
4. **Primitives:**
   - `make_vertex` / `kill_vertex`
   - `make_edge` / `kill_edge` (wires)
   - `set_position`
   - `embed` / `unembed`
   - `split_edge` / `join_edge`
   - `make_face` / `kill_face`
   - `split_face` / `join_faces`
   - `flip_face`
5. **Local validation.** `validate_local(k, touched)` covers the combinatorial and
   embedding checks restricted to touched elements, plus face–face contact for touched
   faces against the rest.
6. **Compaction** of tombstones in identity order, plus the generation fix for
   re-allocated slots.
7. **Projected-face edit rules** (A1-R1).
8. **Randomised edit tests**, an undo/redo hash oracle and a determinism golden.

**P3b** (a separate plan after P3a):
- `imprint` / `unimprint`;
- `add_hole` / `remove_hole`;
- `merge_vertices` / `split_vertex`;
- `connect_loops` / `disconnect_loops` (transient);
- incremental region maintenance once region identity is made stable under splits
  (OI below);
- performance work: an ID index, and batching.

**Not primitives (a deviation from design 01 §7):**
- **`set_region`, `make_region` and `kill_region` are dropped.** Regions stay
  **derived** (OI-2): `build_regions` is the only writer of region and shell columns.
- **Every edit that changes the face set or face geometry sets `regions_dirty`.** Only
  edits that leave every face side, plane and nesting untouched keep regions:
  `split_edge`, `join_edge`, `embed`/`unembed`, and `make`/`kill` of wires and
  isolated vertices.
- **Why the fast paths of design 01 §6 can't work:** region IDs derive from minimum
  face-side IDs, so a `split_face` fast path can't match the `build_regions` oracle.
  This is recorded as **OI-P3-1** for P3b. Candidate fix: region identity from a stored
  seed side or a hint that survives splits.

## 3. Design

### 3.1 Editor and transactions (`topo/edit/editor.h`)

```cpp
template <geom::CoordType C> class Editor {
public:
  Editor(Complex<C> &k, Journal *journal = nullptr, const PropagationRules *rules = nullptr);
  // grouping: several primitives as one undo unit (a "tool" step)
  void begin(std::string_view label);  bool commit();  void rollback();
  // primitives return a Result<T>{code, value}; failure leaves k bit-identical
  ...
  EditReport &report();     // last failure: EditCode, element, message
};
```

**Every write goes through the editor's write API:**
- `set<D, "col">(row, v)`, `touch(group, row)`, `alloc(domain)`, `free(domain, row)`,
  and the `mix` wrapper.
- Before the first write to a `(group, row)` in a transaction, the editor captures
  **every column's bytes for that row** (`get_bytes`): **row-granular physical undo**.
- **Allocator events** are recorded: pop from the free list, append (group grew), and
  free (push). The inverse is a push back, a shrink, or a pop.
- **Scalar complex state** is captured once per transaction: `regions_dirty`,
  `frozen_stamp` and the `caches` validity.

**Rollback** replays the captures in reverse:
1. restore the row bytes;
2. undo the allocator events;
3. shrink the groups to their recorded sizes;
4. restore the scalars.

The content hash afterwards is **bit-identical**. It is page-independent, so restored
pages may be distinct buffers.

**Primitives never write columns directly.** One mutation check plants a direct write
and confirms the undo-hash oracle catches it.

**Failure codes** form `EditCode`: precondition codes per primitive, plus the
validation codes, which map from `ValidateCode`.

### 3.2 Journal (`topo/edit/journal.h/.cc`)

```cpp
struct OpRecord {            // logical, for redo / lineage / diff
  OpKind kind; util::Vector<uint32_t> args; util::Vector<PersistentId> ids;
  util::Vector<geom::Point<C>-bytes> points;  // canonical bytes, coordinate-type tagged
};
struct Lineage { PersistentId parent, child; LineageKind kind; };  // split / merge / derived
struct Txn {
  util::string label; util::Vector<OpRecord> ops; util::Vector<Lineage> lineage;
  RowCaptures captures; AllocEvents alloc; Scalars before;   // physical undo
};
class Journal : public litestl::attr::RefRoot-adapter { ... undo(k); redo(k); ... };
```

**Undo and redo:**
- **Undo** = rollback of the transaction's physical captures. It is exact.
- **Redo** = re-execute the transaction's `OpRecord`s through a fresh editor. After an
  undo the state is bit-identical to the pre-state, allocator included, and the
  primitives are deterministic, so redo reproduces the post-state exactly. A debug check
  compares content hashes.
- **Branching.** A new transaction after an undo truncates the redo tail.

**Lineage:** `journal.forward(id)` returns the children of an ID across committed
transactions, and `backward` returns its parents. Design 04 §6's diffing and
incremental re-export can build on the touched-row sets.

**Pool roots.** `JournalRoots(journal, k)` is an `attr::RefRoot` adapter. For every
captured row of a column with `holds_refs()`, it calls
`visit_elem_refs` / `remap_elem_refs`. It is tested against an external `PoolStore` and a
dynamic `Column<PoolRef>` on faces. `Complex` gets no store until P4.

**Barriers.** Compaction, freeze, `build_regions` and `read` change indices or replace
domains wholesale. The editor exposes them as **barrier transactions**: their
"capture" is a full snapshot of the complex (O(pages), copy-on-write), and undo restores
the snapshot. Undo across a barrier is therefore exact too.

### 3.3 Propagation (`topo/edit/propagate.h`)

**Event kinds and their default policies:**

| Event kind | Sources and weights | Default policy |
|---|---|---|
| **Split** | the parent, with the child's measure fraction | `CopyFirst`; or `Interpolate` with weight = fraction for `SplitByMeasure` columns |
| **Merge** | the parents, with measure fractions summing to 1 | the column's default: floats `Interpolate`, which with these weights is a measure-weighted mean; integers and others `CopyFirst`. The `Sum` rule uses weight 1 per source |
| **Interp** | a new vertex on an edge: `(v0, v1)` with `(1 − t, t)` | the column's default (floats interpolate, others copy `v0`) |
| **Create** | none | the column default |
| **Reverse** | a face's two side rows | swapped by a simultaneous `CopyFirst` mix `{2f ← 2f+1, 2f+1 ← 2f}` over all non-`Topo` face-side columns. `.fs.hint` is `Topo`, so the editor swaps it itself |
| **Delete** | — | none (`free` resets) |

**`PropagationRules`** maps a column name to per-event overrides: `SplitByMeasure`,
`Sum`, `CopyFirst`, `SetDefault`, `Custom`.

**Temp and Derived columns** get `SetDefault` for every event; they are recomputed.

**Measures** (lengths, areas, `t`) are computed by the primitive in `double`, through
`CoordTraits::to_double`. The propagator never sees geometry.

**Execution.** Each primitive collects its events, captures the target rows, then calls
`AttrGroup::mix` once per (group, kind). `Topo` columns are skipped by `mix` itself.

### 3.4 Primitives (P3a)

These rules apply to every primitive:
- **Preconditions** are checked first, without writing.
- **The topology change** goes through editor writes.
- **Propagation** follows.
- **`validate_local`** runs on the touched set. On failure, the transaction rolls back
  with the validation code.
- **Lineage** is recorded.

| Primitive | Preconditions | Effect | IDs |
|---|---|---|---|
| `make_vertex(p, id, container)` | ID unused | Isolated vertex; container as given | given |
| `kill_vertex(v)` | `v` isolated (no edges) | free | — |
| `make_edge(a, b, container, id = edge_id(a, b))` | `a ≠ b`; no edge `a`–`b` exists (no multi-edges in P3a) | Wire. Appended to both disk cycles after `.v.e`'s prev, i.e. at the end; `.v.e` set if `NONE` | `edge_id` of the vertex IDs |
| `kill_edge(e)` | wire (`.e.c == NONE`) | Unlink from both disk cycles; fix `.v.e`; free | — |
| `set_position(v, p)` | — | Writes `pos`. Re-checks planarity or projectability of incident faces, re-derives the radial cycles of every edge of those faces, and checks face–face contact. Sets `regions_dirty` if `v` has faces | — |
| `embed(x, container)` / `unembed(x)` | `x` an isolated vertex or a wire; region containers need clean regions | Writes the container; validates container geometry | — |
| `split_edge(e, p)` | `p` strictly inside segment `e`, exactly (collinear plus strict betweenness, by exact predicates) | New vertex `v`. `e` keeps the half at `vs[0]`; a new edge takes the half at `vs[1]`, and replaces `e` at `vs[1]`'s disk position. Every coedge of `e` splits, the new coedge inserted after it in its loop or before it by sense. The new edge's radial cycle mirrors `e`'s. `.l.size`++ | The halves get `derive(OpDerived, e.id, "split_edge", r)`, where `r = 0` for the half adjacent to the endpoint with the smaller vertex ID; `v` gets `derive(OpDerived, e.id, "split_edge.v")` |
| `join_edge(v)` | `v` has degree 2, and its edges `e1`, `e2` have the same set of loops in their radial cycles with matching coedge pairs; the three points are collinear | Inverse topology: the survivor is the edge with the smaller ID; the other edge and `v` are freed | Survivor keeps its ID; lineage `merge` |
| `make_face(loops, id, flags, hints[2])` | Each loop is a vertex sequence whose consecutive pairs have **existing** edges (exactly one each); the face doesn't use an edge twice; ID unused | Allocates the face, loops and coedges, then inserts each coedge into its edge's radial cycle by **re-sorting the cycle with `radial_order`**. A tie fails; `.e.c` is reset. Planar, else projectable (when the complex allows it), with the same axis rule as the builder. Sets `regions_dirty` | given; loops `loop_id(face, ordinal)` |
| `kill_face(f)` | — | Unlinks every coedge from its radial cycle (fixing `.e.c`), frees the coedges, loops and face; edges become wires if bare. Sets `regions_dirty` | — |
| `split_face(f, a, b)` | `a` and `b` are vertices of the same loop of `f`, not adjacent along it; no edge `a`–`b`; the chord is strictly inside `f` (local embedding check after the split) | Chord edge `e` (two coedges). The loop splits into two. The child on the *left* of `a→b`, in the face frame or projection, keeps `f`'s slot; the right child is new. The other loops (holes) go to the child whose outer loop contains them, by exact point-in-polygon on a hole vertex. Projected faces: both children keep the axis and must stay projectable. Sets `regions_dirty` | children `derive(OpDerived, f.id, "split_face", side)` with L = 0, R = 1; chord `edge_id(a, b)`; lineage `split` |
| `join_faces(e)` | `e` has exactly two coedges, on different faces `f1` and `f2` that have the same flags (projection axis included) and are coplanar, or co-projectable for projected faces; the combined loops are valid | Removes `e`'s coedges and splices the two loops; `f2`'s other loops move to the survivor (smaller ID); `e` is freed; the merged face is validated. Sets `regions_dirty` | Survivor keeps its ID; lineage `merge` |
| `flip_face(f)` | — | Reverses every loop (swap next and prev, toggle sense, `.c.v` becomes the old end vertex), swaps the side rows (Reverse event plus `.fs.hint`) and the `.f.region` / `.f.shell` pairs, and toggles the `Reversed` flag. Radial cycles are unchanged as sets and orders; re-validated. Sets `regions_dirty` | unchanged |

**Disk insertion order** is "append at the end of the cycle". It is deterministic but
differs from the builder's index order. The validator accepts any consistent cycle.
`.v.e` is kept when still valid.

**Uniqueness of IDs:**
- The editor keeps a lazily built `PersistentId → index` map per domain.
- It is invalidated by rollback and undo, and rebuilt on demand.
- Allocation and free update it.
- A duplicate ID is an error.

### 3.5 Projected faces (A1-R1, settled here)

- **`T(f)` stays derived, never persisted.** A projected face's geometry is
  *the canonical CDT of its loops' projection along its axis*. So any edit of its loops
  or vertex positions redefines its geometry, by design.
- **Rule.** After an edit that touches a projected face's loops or vertex positions
  (`split_edge`, `set_position`, `split_face`, `join_faces`, `flip_face`), the editor:
  1. re-runs `cdt_proj` with the **same axis**, and fails if the face isn't projectable
     there;
  2. re-derives the radial cycles of **every** edge of the face, because `T(f)` changed
     its half-planes;
  3. re-checks face–face contact for the face.
- **The axis is never re-chosen by an edit.** It changes only through a rebuild.
- **`make_face`** chooses the axis exactly as the builder does, and needs
  `allows_projectable()`.
- **`split_edge` on any face** changes nothing geometric for planar faces. For
  projected faces it changes `T(f)`, which the rule above covers.

### 3.6 Local validation (`topo/validate_local.cc`)

`validate_local<C>(k, const Touched &t, ValidationReport &rep)`, where `Touched` holds
sorted unique vertex, edge, loop and face sets. They are expanded internally to the
1-ring that the checks need.

- **Combinatorial**, restricted to:
  - edges in `t` and edges at touched vertices;
  - disk cycles of touched vertices;
  - radial cycles of touched edges;
  - loops and faces in `t`;
  - vertex links of touched vertices.

  Duplicate IDs are checked through the editor's ID map. Region checks are skipped:
  regions are dirty or unchanged.
- **Embedding:** planarity and projection of touched faces, hole winding, radial order
  re-derived for touched edges (starting at `.e.c`), and container geometry of touched
  isolated vertices and wires.
- **Contact:** loop simplicity and holes for touched faces, and exact face–face contact
  of touched faces against every other face. Candidates are filtered by an axis-aligned
  bounding box in an O(F) scan; a grid is P3b.
- **Implementation.** Refactor `Checker` and the geometric checks to take an element
  filter, so the whole-complex `validate` and `validate_local` share code. A full
  `validate` with a filter of "all" must give an identical report; a test compares
  them on every generator family.

### 3.7 Compaction (`topo/compact.h/.cc`)

- **`compact(k)`** drops tombstones in every domain, keeping live slots in index order.
  It factors `identity_map` and `new_generations` out of freeze.cc and uses
  `permute` + `remap_group`. The face sides follow.
- It is a journal barrier. The owner triggers it, for example when tombstones exceed
  about 25% of a domain.
- **Container fix.** A container whose target was dropped can't occur (the editor never
  frees a referenced container). It is asserted.
- **DEC-014 generation limit, fixed:**
  - Each domain keeps a high-water `.gen` across shrinks: `Domain::gen_floor`, carried
    by permute and resize, and serialised as a per-domain u32 in a new UTCX format 2.
  - A re-allocated slot starts at `max(gen_floor, old gen) + 1`.
  - Format 1 streams still read (`gen_floor = 0`).

  *Alternative for the reviewer:* leave this fix to P3b.

### 3.8 Determinism

- **Primitives are deterministic functions of the state and their arguments.** There
  is no hashing of pointers and no unordered iteration. `radial_order` is already
  canonical.
- **Allocation is LIFO** in memory. After `read`, the descending rebuild applies; this
  is documented, and the tests compare in-memory sequences only.
- **A fixed random edit sequence on a fixed model gives a pinned content hash** for
  `double` and `Lattice`, and the same topology hash in both.

## 7. Risks

- **R1 — Scope.** P3a is large, larger than P2a. The split point W5/W7 is available:
  W7 can move to P3b.
- **R2 — Validator refactor regressions.** Mitigated by the filter-"all" equivalence
  test over every generator family and the existing corruption tests.
- **R3 — Face–face contact cost** O(F) per edit. Acceptable for interactive and test
  sizes; a grid comes in P3b.
- **R4 — Redo by re-execution** depends on exact determinism. It is asserted by the
  hash check in debug and in the tests.
- **R5 — The region identity instability (OI-P3-1)** blocks incremental regions. Every
  face edit therefore needs a `build_regions` pass before region queries, which costs
  O(model) per interactive step that needs regions.
