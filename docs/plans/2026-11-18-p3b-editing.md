# Plan P3b — compaction, remaining primitives, region relabelling, editor scaling

- **Status:** **v1** (draft, before review).
- **Follows:** [P3 / P3a](2026-11-18-p3-editing.md) (implemented; §2 lists P3b's scope,
  §11 records what P3a left open). Design: [07 §14](../design/core-data-model/07-topology-api.md#14-editing-topoedit-p3a),
  [01 §6–7](../design/core-data-model/01-cell-complex.md#6-shells-and-regions-maintenance-model),
  [04 §6–7](../design/core-data-model/04-identity-versions-journal.md#6-journal), DEC-014, DEC-016.
- **Branch:** `session/p3-editing` (continues from P3a; nothing merged yet).

## 1. Goals

1. **Handles stay safe across shrinking.** A dropped slot that is later re-allocated
   never revives an old handle. This closes the DEC-014 limit and C13's "handles to
   shells and regions are invalidated by any rebuild" gap.
2. **Compaction while editing.** Tombstones can be dropped without freezing, as a
   journaled barrier.
3. **The remaining design 01 §7 primitives** that a consumer needs now:
   - `imprint` / `unimprint` (P4's "road imprinted on terrain sheets" needs it);
   - `add_hole` / `remove_hole`;
   - `merge_vertices` / `split_vertex`, plus `merge_edges` (new; see §3.4).
4. **Face splits and joins keep regions clean** (OI-P3-1) by relabelling instead of a
   full rebuild, bit-identical to `build_regions`.
5. **A merged room keeps its sensors** (OI-P3-2): container hints resolve through any
   hint a region carries, not only the winning one.
6. **Editing cost independent of model size** in `Local` mode: no O(N) scans per
   primitive.
7. **Validator gap closed:** wires crossing faces are reported.

**Not in P3b:**
- **`connect_loops` / `disconnect_loops`: dropped.** Design 01 allows them only
  transiently inside operators, and no operator in P3b (or planned for P4) needs a
  bridge. `imprint` refuses chains that would need one.
- **An exact integer remainder rule for split-by-measure.** It needs a litestl policy
  and no consumer has asked for one.
- **Dirty tiles.** Tiles don't exist yet.

## 3. Design

### 3.1 Generation floor (W1)

- **State.** Each `Domain` gains `gen_floor_` (u32, default 0): no handle with
  `gen ≥ gen_floor_` was ever issued for a slot at an index ≥ the current capacity.
- **Raised by shrinking only:**
  - `permute(map, new_size)`: `floor = max(floor, max gen of every dropped or moved-away
    old slot + 1)`, computed before the rows move;
  - **replacing a derived domain** (`build_regions`, `relabel_regions` rewrite shells and
    regions): `floor = max(floor, max old gen + 1)` over the old rows.
  - **Not** raised by the editor's rollback resize. Rollback restores the floor that
    the savepoint recorded, so a rolled-back edit stays bit-identical.
- **Used by growth.** A slot appended past the capacity (`alloc` with an empty free
  list, `alloc_n`) starts at `gen = floor`. Freed-and-reused slots keep the existing
  `+1` rule. Moved slots keep freeze's `max(own, slot's old) + 1` rule, now also
  `≥ floor`.
- **Rows rebuilt by `build_regions`** start at `floor` (after raising it). Every rebuild
  therefore invalidates every shell and region handle *detectably*; P2 left them able
  to resolve to a different shell or region.
- **Serialised.** UTCX format 2 writes seven floors (one per domain; face sides follow
  faces, and the global group has no allocator) after the header. Format 1 still reads,
  with floors 0.
- **Hashed.** `content_hash` and `topology_hash` append the floors only when any is
  non-zero, behind a marker byte. All-zero states hash exactly as before, so the P0–P2
  goldens hold.
- **Golden impact.** The P3a random-test golden changes: its region rebuilds now bump
  shell and region generations. It is re-pinned once, with this reason recorded.

**`compact(k)` (free function, `topo/compact.h`).**
- Drops tombstones in every domain, keeping live slots in index order. Faces and their
  side rows move together.
- Factors `identity_map`, `gens_of` and `new_generations` out of `freeze.cc`; freeze
  calls the same code for its Morton maps.
- Stored indices are rewritten with `remap_group` (`remap.h`); the remap table's
  compile-time coverage applies.
- Containers: a container whose target was dropped can't occur (the editor never frees
  a referenced container). It is asserted.
- Returns the per-domain maps so a caller can fix its own indices.

**`Editor::compact()`.** A barrier transaction (§3.2): it captures every group whole,
runs `compact`, invalidates the editor's indices and records an op. Redo re-runs it;
compaction is deterministic.

### 3.2 Whole-group captures (W2)

- **Problem.** P3a's barrier copies the whole complex into the transaction. W4 needs
  primitives inside ordinary transactions that rewrite *all* shells, regions and the
  region columns of faces and sides, which per-row capture makes O(F) in bytes.
- **Mechanism.** `TxnLog` gains `GroupCapture{g, epoch, AttrGroup copy, allocator state
  (free heap, live count, floor)}`. Copying a group is O(pages) and copy-on-write.
  - `touch_group(g)` captures group `g` once per savepoint epoch, after which row
    captures for `g` in that savepoint are skipped.
  - Rollback restores group captures *after* replaying the row captures of the same
    savepoint, in reverse order of capture.
- **The barrier becomes** "capture all nine groups whole". `Txn::snapshot` and
  `barrier_snapshot_` go away. `rebuild_regions` and `compact` are then ordinary
  primitives that may run inside a user transaction.
- **`JournalRoots`** visits group captures like it visited the snapshot (whole
  columns).
- **Dynamic column pointers** still dangle after undoing a group capture (§11 of P3a);
  documented as before.

### 3.3 `build_regions` stages and container hints (W3)

- **Stages** (same results, new seams in `regions.cc`):
  1. `partition_shells` (union-find over wedges; combinatorial);
  2. `classify_and_nest` (kinds, volumes, ray tests; geometric);
  3. `label_regions(partition, shell → provisional region)` (IDs, order, chains,
     shell and region rows, region column carry-over by ID, container resolution).
- **Container hints (OI-P3-2).** A container hint resolves to the unique region whose
  face sides carry that hint (any side, not just the winning hint). `HintConflict`
  stays a warning.
  - **Ambiguous** if two regions carry it; **Unresolved** if none does.
  - The P2 rule ("the region whose winning hint it is") is the special case where every
    region carries one hint, so every P2 test keeps its result. Verified by the P2
    goldens.
- **P3a's `hint_in_use` / `HintInUse` (C7) checks stay**: they guard the last carrier.

### 3.4 Primitives (W5, W6)

**Common rules.** Everything from P3a applies: savepoint per primitive, `Prim`,
propagation events, lineage, failure codes, ID uniqueness, `regions_dirty` unless a
fast path (§3.5) applies.

**`imprint(f, chain)` / `unimprint(e)`.** `chain` is a list of wire edges embedded in
face `f`, given in path order.
- **Split case:** the chain is a simple path from `a` to `b`, two distinct vertices of
  `f`'s outer loop. Every interior chain vertex is embedded in `f` and has exactly the
  two chain edges. Effect: as `split_face`, with the chain as the chord. Chain edges
  lose their container and gain two coedges each; interior vertices lose their
  container.
  - Children: `derive(OpDerived, f.id, "imprint", 0 | 1)`; the child holding the chain
    coedges `a → b` keeps `f`'s slot (as `split_face`).
  - **`split_face` shares the core** (`split_face_core(f, path, ids)`), keeping its own
    IDs and allocation order, so P3a's behaviour and its unit expectations are
    unchanged.
- **Island case:** the chain is a closed simple cycle whose vertices are all embedded in
  `f`. Effect: the cycle becomes a new hole loop of `f` and the outer loop of a new face
  `g` filling it; inclusions inside the cycle move to `g`.
  - `f` keeps its ID; `g = derive(OpDerived, f.id, "imprint.island", min chain edge
    ID)`; the hole's loop ID is `loop_id(f.id, ordinal)`, ordinal = position.
  - `g`'s front faces the same way as `f`'s front; hints copy from `f`.
- **Refused:** an endpoint on a hole loop, endpoints on different loops (a bridge), a
  chain touching a loop at an interior vertex, a chain vertex with other edges, a chain
  edge not embedded in `f`, a non-simple chain (`ChainNotSimple`), an inclusion on the
  chain (`InclusionOnChord`), a degenerate child (`DegenerateLoop`).
- **`unimprint(e)`** inverts both cases from one chain edge: it walks the maximal chain
  through `e` whose edges have exactly the two faces `f`, `g` and whose interior
  vertices have degree 2. It requires what `join_faces` requires (coplanar, equal
  flags, surface and hints, consistent fronts).
  - Split case: survivor = the smaller face ID, the other face is freed, the chain's
    edges and interior vertices become embedded in the survivor.
  - Island case (the chain is `g`'s whole outer loop and one of `f`'s holes): `g` is
    freed, the hole loop removed, the chain embedded in `f`; `g`'s inclusions move to
    `f`.

**`add_hole(f, chain)` / `remove_hole(f, loop)`.**
- `add_hole`: a closed simple chain of wires embedded in `f`, strictly inside the outer
  loop and outside the other holes (exact point tests on every chain vertex, plus
  validation for crossings). Refused if an inclusion of `f` lies inside the cycle
  (`ContainedElement`) — the opening would leave it floating.
- `remove_hole`: the hole's edges must carry no other coedges (`EdgeShared`); they and
  the hole's vertices become embedded in `f`. Later holes' loop IDs are renumbered to
  their new ordinals (lineage records the renames).
- Both set `regions_dirty` (the geometry of the face changes).

**`merge_vertices(a, b)` / `split_vertex(v, edges)`.**
- `merge_vertices`: exact equal positions (`Coincident` otherwise), no edge between
  them (`Adjacent`), no vertex `x` with edges to both (`EdgeExists`; merge the edges
  first with `merge_edges`). Survivor = the smaller ID. Disk cycles are concatenated in
  canonical order (the survivor's first).
  - **Containers:** if both are free or have equal containers, kept; if exactly one has
    coedges (a face vertex), the result has none; otherwise `Incompatible`.
  - Regions stay clean: no face side or wedge changes.
- `split_vertex(v, edges)`: moves `edges` to a new vertex at `v`'s position, ID
  `derive(OpDerived, v.id, "split_vertex", min moved edge ID)`. The set must be closed
  under face corners at `v` (both edges of every corner of a moved coedge), else
  `SplitsCorner`.
  - **Validation catches** the remaining invalid cases: a split vertex whose faces then
    touch at a point (`FaceContact`).
- Propagation: `Merge` with equal weights; `Split` copies.

**`merge_edges(e1, e2)`** (new; needed so `merge_vertices` can weld shared walls and
snap wires onto face edges).
- Same endpoint set; survivor = the smaller ID; the other's coedges move to the
  survivor and the radial cycle is re-sorted (`RadialTie` fails).
- A wire absorbed into an edge with coedges loses its container. Two wires: containers
  must match.
- Regions: dirty when coedges move (wedges change); clean when only a wire is absorbed.
- No inverse primitive. Undo covers it, and no consumer needs to un-weld.

### 3.5 Region relabelling and fast paths (W4)

- **`relabel_regions(k)`** — regions must have been clean before the edit, and the
  partition into shells must map one-to-one onto the old shells:
  1. run `partition_shells`;
  2. map each new shell to the old shell of any of its sides that existed before (every
     new shell has one: the surviving parent side);
  3. if two new shells map to one old shell, or one new shell to two old ones, return
     *not applicable* (the caller sets `regions_dirty`);
  4. take kind, volume and region from the old shell;
  5. run `label_regions` (§3.3).
- **Why it equals the oracle.** The edits that use it leave the union of every shell's
  geometry unchanged, so kinds, volumes and nesting are unchanged. Only labels (IDs
  from minimum side IDs, row orders, chains) change, and `label_regions` is the code
  `build_regions` runs.
- **Fast paths** (planar faces only: a projected face's surface is its
  triangulation, which a split changes):
  - `split_face`, `imprint` (both cases), `join_faces`, `unimprint`, and `split_edge`
    / `join_edge` on edges of projected faces (P3a sets these dirty; with planar
    neighbours only they are now clean).
  - The new child rows copy the parent's `.f.region` / `.f.shell` before relabelling.
- **Journal.** `relabel_regions` runs under whole-group captures of shells, regions,
  faces and sides (W2).
- **Option.** `EditorOptions::keep_regions` (default on). Off restores P3a behaviour,
  which the tests use as the oracle path.

### 3.6 Editor scaling and validation (W7)

- **Inclusion index.** The editor keeps `container → sorted elements` for faces and
  regions, updated by one write helper used for every container write (`set_container`).
  It is marked invalid on rollback, undo, redo and outside writes, and rebuilt lazily.
- **Hint index.** Counts of side carriers and container users per hint, same
  maintenance. `hint_in_use` and `hint_carried` become O(log N).
- **Filtered combinatorial layer.** `validate_local` checks only touched rows and
  their one-ring (disk, radial, loop and face links), plus ID uniqueness of touched IDs
  through the editor's ID index. The full layer remains the oracle in `Full` mode.
- **`ValidateMode::OnCommit`.** Validation runs once at the outermost commit over the
  union of touched rows; a failure rolls back the whole transaction. For procedural
  edit batches.
- **Wire–face crossings** (Global layer): a wire edge may meet a face only at a shared
  vertex or, if embedded in that face, lying on it. Exact segment–triangle tests over
  the contact grid, against `T(f)`. New code `WireCrossesFace`.

### 3.7 Determinism

- All new primitives are deterministic functions of state and arguments. Chain walks
  start at the given edge and follow vertex order; merges choose survivors by ID.
- `relabel_regions` and `build_regions` share `label_regions`, so the oracle compares
  like with like.

## 4. Tests (W8)

**Unit (`test_edit_primitives`, a new `test_edit_primitives_b`):**
- each new primitive: effect, every refusal code as a bit-identical no-op, undo/redo
  hashes, lineage, propagation;
- imprint of a 3-edge chain splitting a wall; island imprint and unimprint round trip;
- a window built by `add_hole` + `make_face`; `remove_hole` refusing a shared edge;
- welding two separately built boxes: `merge_vertices` ×4, `merge_edges` ×4 →
  validates, regions rebuild to the shared-wall result of the builder (same topology
  hash as building the pair directly, modulo IDs — compared by structure);
- generation floor: compact, re-allocate, old handles don't resolve; format 1 and 2
  round trips; floors zero hash as before;
- `compact` + undo + redo; compaction inside a user transaction rolled back;
- OI-P3-2: kill the wall between two rooms, then the rebuild succeeds and the sensor
  resolves to the merged room;
- projected face on a three-face edge (the P3a coverage gap): `set_position` changing
  the radial order.

**Random (`test_edit_random`):**
- new primitives in the step mix; `compact` and `merge` steps;
- `keep_regions` on vs off must reach the same final content hash after a final
  `rebuild_regions` (and Full validation, which includes `RegionsStale`, checks every
  fast path as it happens);
- Local vs Full vs OnCommit equivalence;
- golden re-pinned (reason: §3.1).

**Benchmark (`bench_edit`, not in ctest):** a room-grid city at 10⁴ and 10⁵ faces; per
primitive time in `Local` mode must stay within 2× between the sizes.

**Mutation checks:**
1. alloc past capacity ignores the floor;
2. rollback doesn't restore the floor;
3. group capture restored before row captures;
4. relabel skips the one-to-one check;
5. container hints by winning hint only;
6. imprint leaves a chain vertex's container set;
7. inclusion index not updated on `split_face`;
8. filtered combinatorial layer skips the one-ring;
9. wire–face test ignores embedded wires' own face rule;
10. `merge_vertices` keeps a face vertex's container.

## 5. Risks

- **R1 — Relabelling equivalence.** Any difference from `build_regions` is a hash
  mismatch, which Full validation reports immediately (`RegionsStale`). The
  not-applicable path keeps correctness.
- **R2 — Group captures and row captures interleaving** in one savepoint. Ordering rule
  in §3.2, mutation 3.
- **R3 — Golden churn.** Only the P3a random golden is expected to change (§3.1).
- **R4 — Scope.** W4 and W7 are the largest. If W4 slips, W5's primitives ship with
  `regions_dirty` and the fast paths follow.

## 6. Open issues

- **OI-P3b-1.** `split_vertex` has no geometric guidance for which fans to move; the
  caller decides. Fine for import repair; revisit with a UI.
- **OI-P3b-2.** Relabelling still costs O(F) per fast-path edit when the region order
  changes (all `.f.region` values shift). Stable region row order (not sorted by ID)
  would make it O(region), but changes the canonical form and every golden. Deferred.
